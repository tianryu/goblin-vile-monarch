# PC 手柄与来访坐骑商人

版本0.12.1，2026年11月7日。以本文件覆盖0.11.0的随时打开坐骑购买面板设计，手机分支不变。

## 使用方式

| 功能 | 键鼠 | 标准手柄 |
| --- | --- | --- |
| 水平移动 | A/D、左右键 | 左摇杆、十字键 |
| 交互、逐枚投币、取币 | E、空格，支持长按 | A，支持长按 |
| 抽鞭 | Q | B |
| 第二操作 | R | X |
| 切换附近目标 | Tab | Y |
| 奔跑 | 按住Shift | 按住LB |
| 快速回洞 | H | RT |
| 暂停 | Esc | Start |
| 操作说明 | F1 | Back |
| 菜单选项 | 上下键、Enter确认、Esc返回 | 摇杆或十字键上下，A确认，B返回 |
| 剧情 | Enter、空格或E继续，Esc跳过 | A继续，B跳过 |

手柄字母采用 Xbox 位置布局。Windows 原生包接入系统 XInput，支持 Xbox 及兼容 XInput 的手柄；其他设备需要对应驱动或平台映射，不宣称已验证 PlayStation 原生直连或 Steam Input。浏览器预览使用标准 Gamepad API。两者汇入 Cocos 正式 `GAMEPAD_INPUT`、`GAMEPAD_CHANGE` 事件，键鼠与手柄共用操作事务。

本机 Cocos 3.8.8 虽提供原生手柄 PAL，却没有 Windows 普通手柄采集实现，因此补充项目内的 `WindowsGamepad.cpp`，未修改全局引擎。系统目录动态加载 XInput，断开设备低频探测，活动设备逐帧读取但只在数据变化时分配事件。失焦释放输入并暂停。特别核对了引擎原生按钮码采用 Nintendo 位置命名，Xbox A/B/X/Y 必须转换，不能照抄名称。

主菜单和暂停菜单都可打开操作说明。首次有效手柄输入会给出短提示，底部键位和引导随最后有效输入切换。摇杆设死区；菜单支持首次延迟后连续移项。跨菜单一直按着A时，必须松开后才能在场景投币，防止一次确认穿透。体力耗尽后必须松开奔跑键。断开手柄清除移动和长按交互，游玩中自动暂停，可接键鼠继续。失焦和返回菜单同样释放输入。

## 坐骑商人

从第2天起，每隔6天清晨进场，走到营地外侧固定停靠点，傍晚108秒开始离开。游戏暂停时来访时间也暂停，不按现实离线时间换货。

0.12.1按最新要求改为第2、8、14、20天等到访。商品继续接着上次轮换，兼容旧两天周期的存档，避免下一次重复商品。此次只重测到访日期、轮换和直接关联交易模型，不重跑手柄或全战役验收；下方原生和模拟手柄结果仍对应0.12.0。

商品按巨蜥、疾风狼、巨蝠、野猪轮换，相邻来访保证不同。定价沿用30、40、50金币，野猪初始已拥有。已拥有且当前未骑乘的当期坐骑可以免费换上；每次来访只成交一次。旧的M随时购买面板已取消，必须靠近营业中的商人操作。

商人身旁展示实际坐骑、名称和数字金币图标；接近后出现投币槽、焦点描边及简短说明。交易通过常规逐币操作完成，未投满就离开或商人打烊会退还已投入金币。后台再次校验距离、营业日期、商品和成交状态，不只依赖按钮禁用。

到访日、商品、位置、进出阶段及是否成交随战役保存，读档不刷新商品，不重复发坐骑。旧PC档缺字段时只补商人状态，保留金币、坐骑和进度。到达时只短暂提醒，不强制引导交易。

## PC 广告清理

移除平台层激励与模拟广告接口、TapTap登录调用、控制器中的广告面板和奖励流程。PC模型拒绝广告回执与旧HUD广告动作。旧存档字段只保留兼容，不发奖励。死亡沿用整顿部落的损失结算，无广告按钮。

## 定向验证

- `scripts/test_pc_controller.cjs`：输入死区与边沿、跨页长按隔离、断开清零、来访轮换、距离与日期条件、逐币退款、一次成交、读档保留商品及拒绝广告奖励。
- `scripts/test_pc_pad_browser.cjs`：用标准浏览器Gamepad接口夹具，经Cocos正式事件进入游戏，核对菜单、剧情、移动、帮助、切目标、长按买坐骑、重复按键、断开暂停、键鼠接管及中英文。
- `scripts/test_pc_browser.cjs`：键鼠和双语相关回归。
- `scripts/test_pc_native_pad.cmd` 编译实际 C++ 映射，`scripts/test_pc_native_pad.cjs` 将其输出接入本机引擎真实原生 PAL，核对八个操作键、摇杆和十字键方向、松开与断开。
- TypeScript检查、Creator桌面预览及Windows Release构建，另核对交付包资源与依赖。

编译联调发现 Creator 的宽松数组展开把 Map 迭代器当成单个元素，已改为显式 `Array.from`。模拟手柄直接开局后，画布未获得键盘焦点，已在浏览器入口补上焦点处理。保留之前失败记录，未把旧版本的通过结论直接移用。

本机没有完成实体手柄验收，标准接口模拟通过不能替代实体 Xbox、PlayStation 或其他手柄测试。原生键盘此前的自动化响应问题仍不能据浏览器结果宣称已解决。完整战役平衡与长时性能不属于本轮重测。

用户明确要求不通过操控鼠标测试，已停止该方式，后续采用代码、输入夹具和构建验收。Windows 新菜单已观察到正常显示，操作说明的原生鼠标点击验收被用户中止，未记为通过。

原生桥接的最终 C++ Release 编译和原生 PAL 映射测试通过，新 ZIP 完整性校验通过。另一次隐藏窗口启动检查在10秒内未读到就绪日志，进程仍存活，不能记为原生运行验收通过，也不能据此判定崩溃；保留 `native-startup.json` 与对应日志，未用这次检查替代实体输入测试。
