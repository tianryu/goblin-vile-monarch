# 横屏交互与画面重做

本轮客户端布局和交互已完成本地整改，验收与未验证项见下文。上一轮181项是历史基线，不能当作本轮证据。

用户要求：修复模糊、转身锚点、背景接缝；靠近显示对应数量的金币虚影及下一等级建筑虚影，通过投币逐格完成交互；寻找适合手绘风格的开源字体；所有页面先出优化布局图再实现，主要按钮放在双手拇指容易触及的底部两侧；建筑与职业成长有不同外观；现有水纹理通过程序化动画产生流淌波动。角色帧动画继续延后。

授权变化：可参考pixelfx的确定性、局部坐标、分阶段时间曲线、少量粒子与前后层次，制作非像素手绘色块特效；可用现有水纹理做UV流动和波动。角色、建筑、道具及UI位图仍独立AI生成，不能扩张为任意程序代画。

已定位：Godot负宽度绘制已经在原位置翻转，现有代码再次增加宽度导致转身横移。整层世界固定480高的离屏纹理再放大造成二次采样模糊。背景直接首尾拼接，左右边界不一致；固定原生宽度交替镜像形成连续循环，检查多个接缝与视口尺寸。

设计方法：先以实际AI素材、开源字体和独立布局原型生成逐页设计图，标记为布局设计稿，不冒充运行截图；再按同一布局参数实现Godot，分别保留设计图和运行图。页面包括主游戏、欢迎、工具、金币、援军、坐骑、监牢、交易、盗贼、出征、暂停、手册、账本、重开、胜利、失败、加载、错误和横竖屏提示。商品卡用于选择，确认/购买/派遣集中在底部；高频操作无需点击窗口右上角。

成长方案：大厅等级决定己方工匠、猎手、打手与盗贼的装备阶级，共三阶，各有独立造型；二、三阶自动换装，规则和数值共用数据。大厅、路障、监牢已有等级图继续检查；箭台、吊网与落石架补齐第二等级独立外观。不新增逐个士兵点选升级。

投币方案：每次投一枚，可连续按住，也可分次轻触。未完成时金币槽保留进度；离开、暂停、后台或目标失效退回未提交的钱，按普通金币/广告金币/储备来源精确归还。最后一枚完成才扣废铁和提交招募或施工，避免重复扣费。按住经过另一目标不串操作，完成一次后松手再开始下一次。

参考：

- [霞鹜文楷](https://github.com/lxgw/LxgwWenKai)，OFL字体；游戏子集重命名为Goblin Hand UI，保留上游版权与完整OFL。
- [Godot矩形翻转实现](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/rendering/renderer_canvas_cull.cpp#L1531)，负宽度仅翻转并取正尺寸，不增加位置。



## 本轮实现与验收结果

本轮客户端布局与交互整改已完成本地验收。23张逐页布局设计图在art/design/interaction-v5，按同一设计实现的运行截图在qa/interaction-v5。对照页为http://127.0.0.1:42817/art/design/interaction-v5/index.html，正式试玩http://127.0.0.1:42820/，已有页面需要刷新。

现行实现：独立AI纸卡、布幅按钮、底部返回与确认、商品先选择再购买，四页手册、暂停、账本、胜败、启动、错误帮助和竖屏提示。常用按钮落在底部两侧，最短测试横屏740x360上保持至少约48CSS像素触控高度。准确安全区仍需实际手机复核。

投币逐枚实付，可分次轻触或按住。未提交的钱在离开、暂停、后台、失效或取消触摸时按资金来源退款；收齐后才提交废铁与施工。靠近显示对应金币虚影与下一等级建筑虚影，施工虚影在角色后方保留。商店在交互指松开后打开，不穿透购买；Web侧保留touchcancel标识，避免被引擎当成普通松手。

四职业三阶装备随大厅成长；箭台、吊网、落石架第二等级有独立图。角色与坐骑继续用完整静态图，转向以鞍座锚点翻转。世界直接原生绘制，背景循环镜像并裁掉透明范围，水纹理用UV流动、轻微波浪和随时间变化的倒影。短特效采用少量哑光笔触与弧线，借鉴pixelfx的确定性与分阶段时间曲线。角色帧动画仍延后。

本轮253项本地断言通过，分组证据见qa/godot/v5-acceptance.json，不能称为真机认证。三条逐枚投币、无广告与无资源注入的逻辑征程全部取得双旗。原模型43项、整改模型35项、新投币/成长32项、原生UI5项、浏览器99项、DPR2和模拟安全区21项、正式包9项、启动/音频9项。

生产99个部件，33张纹理。己方新装备统一图集，极限场景绘制批次从约143降至约35。运行、启动页与开场图单份RGBA保守合计24144144字节，约23.03MiB，未包含字体、引擎、GPU副本与进程总内存。

最终DPR2桌面Edge软件WebGL持续300秒压力结果：P50 36.4ms，P95 60.5ms，P99 66.7ms，无脚本错误。该场景为60名己方加约40名高耐久敌人和后续波次。P95不超过40ms的内部压力目标尚未达到，不能引用旧版本18.3ms，也不能据此声称低端手机已达标。报告stress-browser-v5.json保留真实结果；此前优化前报告保留对照。

尚未验证：真实Android/iOS手机、TapTap宿主和真实广告SDK、平台发布身份与独立的90%感知相似度评分。23页设计和运行画面分别保存并人工检查，不伪造视觉百分比。未创建、修改、上传或发布平台应用，未下载付费Runway内容。

## 自检发现并修复的具体问题

- 菜单控制器的临时实例被释放，卡片回调失效。改为界面持有一个控制器。
- 交互按下时立即开窗，后续鼠标模拟事件会按到购买键。改为对应手指松开后开启，并消费这一手势。
- Godot Web把取消触摸映射为释放，增加捕获阶段的取消标识。双指中另一指松开不打开商店，取消不打开也不扣钱。
- 九宫格进度条的上下切片大于5/7像素控件，产生越界碎片。改为适合细条的切片，并检查最小尺寸。
- 无限广告产生的长储备数字挤压钱袋与人口。钱袋使用简短加号，详情保留在金币商人和账本。
- 页面手册监牢插图过宽。设计原型按240像素包围盒缩放，实机同样约束长宽。
- 底部安全区压缩卡片后，库存和价格发生重叠。先修订布局稿，再让图片随可用高度收缩；名称、两行说明与价格预留独立区域。新增190像素内容区和DPR2下34CSS像素底部安全区复核，覆盖七类商店。
- 错误说明与重试键重叠。启动幕沿用横屏布局比例，说明与底部按键分区，增加可操作的帮助。
- 重新开始会让镜头从旧位置长距离滑过。新征程立即对齐君主。
- 新职业分散纹理导致混编队伍批次增加。八张独立源图合到共享图集，保留源图和出处。
- 字体每次重复导入不稳定。按字符集合缓存字体子集，导出前独立完成引擎导入。

23张布局原型及73张浏览器场景截图分别保存。逐页人工检查覆盖商人、监牢、盗贼、出征、暂停、四页手册、账本、重开、胜败、加载、错误与旋屏。八种坐骑戴冠/失冠状态分别检查两种朝向。受控广告提供方仅用于测试，不随正式包导出。

[Godot CanvasItem着色器文档](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)说明片元COLOR包含默认纹理颜色，因此水面使用顶点调色varying，防止再次乘入原纹理。
