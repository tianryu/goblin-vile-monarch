# TapTap作品类型与商店标签核查

日期：2026年10月30日。用户提供《我是哥布林：魔王》商店截图，关注测试标签、创意工坊标签，以及“当前关卡创建自该游戏”关联到“策略游戏合集（TapTap测试版）”。本轮仅只读查询，没有切换、修改、上传、发布应用，也没有对外发送消息。

## 已核实的数据

通过get_current_app_info强制刷新，当前连接实际选择的是《我是哥布林：魔王》1007996，开发者510750，miniapp tapmcwbcprpqzmovnp。它不是本项目《君主》1008093。全局连接可能被其他工作切换，每次外部操作前须重新核对目标，不能把项目文档里的目标当作当前连接状态。

通过get_current_app_store_snapshot读取魔王1007996的商店结果：

| 字段 | 值 | 可支持的判断 |
| --- | --- | --- |
| is_level | true | 商店把它作为关卡作品处理 |
| level_info.level_tag | 创意工坊 | 创意工坊为平台作品标签 |
| version status | TRIAL | 当前展示的版本类型属于试玩/测试状态 |

| miniapp.miniapp_id | tapmcwbcprpqzmovnp | 与已选择魔王一致 |

“当前关卡创建自该游戏”及策略合集来自用户截图；结合is_level=true，可解释为平台的关卡来源/归属展示。该字段本身不是源码取自某游戏、AI作品识别或抄袭侵权判定的证据。未取得父级应用ID，因此不能进一步声称已完整查清该合集的后台绑定记录。

另用get_app_status只读查询本项目《君主》1008093：接口返回“关卡游戏状态：未上线(0)；审核状态：未发布(0)”。因此之前的“新建独立应用”只证明分配了不同应用ID，不能当作非关卡独立游戏发布身份已落实。此前没有充分区分这两件事，需要更正。

## 当前官方MCP源码

[TapTap官方应用创建实现](https://github.com/taptap/instant-games-open-mcp/blob/main/src/features/app/api.ts#L214-L227)的createAppForDeveloper调用POST /level/v1/create，参数为developer_id、title、category。当前工具create_app也只暴露名称、开发者、分类，没有独立/关卡发布类型转换参数。这与此次实际查到的关卡身份一致；不能仅凭工具名称create_app保证常规独立上架。

[官方新建和管理游戏文档](https://developer.taptap.cn/docs/store/release/publish/create-game/)介绍常规发布和正式上线流程，但主要描述APK发布，不能据此推断H5关卡可以直接切换成独立正式H5，更不能承诺现有App ID可保留迁移。

## 未核实与后续边界

现有工具没有已确认的作品类型转换或标签移除操作。需要向TapTap开发者后台/平台支持核实：

1. 原生H5是否可以按非关卡独立应用发布、具体入口与要求是什么。
2. 已有1007996和未发布1008093能否迁移，是否保留App ID、关注和既有数据。
3. 当前关卡/H5通道退出TRIAL、去除测试标签及父级合集展示分别需要什么条件。

本轮不代发工单、不改变状态，不为消标签修改游戏标题或伪造“正式版”。技术栈和画风可以继续独立讨论，但修改源码技术栈不能直接改变这些服务器作品类型字段。下一次真正准备发布时，应先把目标App ID、作品身份、发布状态和父级展示确认清楚，再提交具体发布内容供审核。
