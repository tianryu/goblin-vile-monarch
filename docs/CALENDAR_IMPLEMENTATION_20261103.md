# 日期难度调整版 实施与验收

2026年11月3日，用户已授权实施并准备再次测试。本地试玩http://127.0.0.1:42828/，旧V11的42826和固定ZIP保留。当前为Cocos本地Web功能预览，正式目标仍为TapTap小游戏，本批未上传或发布。

## 规则与源码

夜袭规则唯一入口为cocos/assets/scripts/model/CampaignRules.ts的raidPlan(day)，只接收全局日期。五个营地、占领数量、主厅等级均不影响当天人数、兵种比例、强力预算或器械。第1至20天6+2*(day-1)，第21天起44+3*(day-20)，最高80；第1/5/10/15/20/21/25/30/32天为6/14/24/34/44/47/59/74/80。精锐与Boss占人头，器械另算。

第5天重锤巨兵与普通跃墙兵，第10天冲车与重装盾阵，第15天投石车，第20天常规法师、火焰投石车及夜袭Boss，第25天增加焚林导师候选，第30天一辆火焰投石车加一辆普通投石车。第5天起每5天一份强力预算，Boss消耗两份，强力单位穿插队伍而非全堆首批。即使仍在斥候，日期日程照常生效；提前推进不额外提高夜袭档位。舰队统帅仍留守运兵船。

全敌军基础生命、攻击、防御每5天加5%，第100天最高加100%。移除旧阶段血量系数，不复利。存活单位保持当前生命比例，俘虏和尸体不因日期强化；普通普攻、齐射、重砸、火雨、燃烧和器械攻击沿同一成长，已发射的弹道保留发射时伤害。缴获器械保留缴获时倍率，之后不继续吃敌方日期成长。

## 真实兵源

守备与外征使用稳定士兵ID，预备、预留、出征、倒地、撤回、退役、调入守备分别记账。每名外征士兵首次倒地扣一次，绑运与出售不再扣；未入场部队撤销预留不算战果；活人真正撤回才回储备，伤势保留并休整。原营地失守后继续走向后方存活营地，不在玩家已占区凭空回营。

为保障只按天数加压，后方按每晚编制缺额准备新兵和器械，新增记入补员与制造账，不复活被俘个体、不复制缴获车。旧35%补员硬限与靠库存不足削弱后续夜袭的提案取消。守城获得本夜安全、资源与整备机会；核心守备不被夜袭消耗。

开局外征库存12/20/30/40/20是储备分布，不是营地每日出兵上限。留守核心人数15/30/50/70/30包含驻营精锐与Boss，缓慢补员与扩容；主动攻营伤亡照常保留。复建通过新的实际调拨，原被俘的驻营个体不复活。

每个新夜的首批进入战场，避免两支旧队把新日期Boss和器械堵住。其余部队每四秒补入最多六名，普通补入在活跃外征约96名时排队，队列不丢兵、不算伤亡；新夜首批可临时高于该软阈值。此阈值不是手机性能达标结论。

## 地图与城防

世界右界30600，斥候6500、先锋12000、前军18500、中军26500、船28500。洞穴核心不拉散，拉长前段野外。中军宽2400、船宽1400，仅100单位码头过渡，保持最终战区连续。旧档玩家、哥布林、敌人、动物、掉落、器械、运输目标和弹道按区间迁移，保留金币、装备、伤亡和占领。

前两营仅帐篷与士兵，无固定城防。前军一层木墙两座单层塔；中军三道木石铁防线，三座3/2/2层箭塔；船两道入口防线及四处双层射击位。中军7名、船8名塔射手都从真实守军中抽取，船相应将4个矮人名额改给射手，总数仍30。空塔不射击，塔毁后幸存者落地。双方近战攻击塔本体，不能在塔脚隔空砍高处射手。

继续使用已验收的独立AI位图，未开启新生图或序列帧队列。原昼夜、程序火、水波、阵营描边与统一显隐保留。启动静态贴图加载限六项并发，降低一次排入数百项请求的峰值；是否解决所有设备的资源问题仍需手机验证。

102项模型回归、类型检查与第5轮构建通过；第5轮对应的9组浏览器检查通过，零脚本和资源错误。早期第4轮的9项功能本身通过，但出现一次armor_item资源请求ERR_NO_BUFFER_SPACE，原报告保留calendar-browser/final-build4/report.json，整体判未通过。随后加入六项资源加载并发限制并重测，不能声称该偶发错误的底层根因已完全证明。

固定目录在HTTP/1.0本地服务下曾再次出现一次资源ERR_NO_BUFFER_SPACE，保留calendar-package-smoke-http10-failure.json。预览服务改为HTTP/1.1持久连接后，三次新建独立浏览器的冷启动、实际移动与正常存档读回均通过，零脚本错误和失败请求，证据calendar-http11-cold-start-1/2/3.json。归档自带serve-local.py及启动脚本；这证明当前桌面交付的重复启动结果，不证明所有设备的网络问题已经消失。
